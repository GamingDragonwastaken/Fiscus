# Final Gate

The program is not complete merely because repository work stops. Every audit/master-plan item must be `COMPLETED`, `SUPERSEDED`, `EXTERNAL_GATE`, or `REJECTED_WITH_REASON`.

## Repository-internal completion conditions

- [ ] No unresolved repository-internal P0/P1 defect.
- [ ] Exact-head CI green on all configured jobs.
- [ ] Typecheck/build/package smoke green at exact final SHA.
- [ ] Trusted Epistemic Kernel invariants property/adversarial tested.
- [ ] Exact Money/Rate and economic basis semantics migrated.
- [ ] Required-gate unknowns cannot become confirmed realization.
- [ ] Conflict remains distinguishable from unknown.
- [ ] Negative claims require a relevant completeness witness.
- [ ] Granularity/construct/evidence/trust escalation requires explicit witness.
- [ ] Raw evidence/issued claims are immutable or explicitly versioned/superseded.
- [ ] Causal and observational lanes are semantically separate.
- [ ] Decision recommendations expose assumptions/identified ranges/fitness.
- [ ] Canonical API/GUI/CLI contracts are conformance-tested.
- [ ] Documentation matches runtime or is mechanically generated/checked.
- [ ] Recovery/migration/security/supply-chain gates verified.
- [ ] External gates have executable protocols and explicit blockers.
- [ ] Final adversarial audit attempts to falsify completion and all surviving internal defects are repaired.

## Completion language

Do not claim perfection, historic significance, field leadership, or scientific novelty from internal implementation evidence.
